## Historical phases 1–4 source snapshot

## Change and decision

The candidate reduces coordination with no new evidence while retaining the
goal, authority, ownership, meaningful recovery state, and actual acceptance.
It changes four existing policy Skills. The lifecycle entry adds only a short
change trigger; detailed coordination and validation decisions stay in their
own modules. No tool dependency, state engine, hook, or mandatory Plan is added.

Coordination retains an evidence identity and a compact continuation packet,
uses bounded waits, and sends one actionable feedback package per issue.
Validation reuses an applicable result, checks changed obligations, and
distinguishes an invalid product claim from an unfit acceptance method.
Demonstrated invalidity requires immediate correction of the affected path.

## Semantic review cases

These are a review of the written policy, not measured Agent executions.

| Case | Required decision | Boundary retained |
| --- | --- | --- |
| Same progress cursor, same artifacts, no external fact | Back off or do independent work; do not replay full history, feedback, or review | No new semantic delta is invented |
| Missing cursor or uncertain worker status | Resolve uncertainty with a targeted check | Unknown is not treated as unchanged or successful |
| New progress, blocker, deadline, or ownership risk | Check the affected evidence, update its consumer, record meaningful state | Change remains visible; one owner per writable scope |
| Review passed and its input/evidence remain applicable | Reuse the result | New edits or stale evidence still reopen affected obligations |
| Source contains a read in an uncalled closure or a false branch | Text alone cannot prove execution; obtain a behavioral observation or narrow the claim | Actual task quality and product acceptance remain required |
| A static checker accepts string-only read text, receiver rewriting, or overwritten taint | Retain the counterexample and reassess the method | No endless expansion of the checker as an implicit product prerequisite |
| A quiet owner is still active | Inspect bounded evidence before replacement | No overlapping replacement writer |
| Source checks pass but the candidate is not installed | Report a validated source delta | No claim of live adoption or measured Token savings |

The approved optimization plan suggested a starting reassessment budget of
three same-cause failures or two consecutive falsifications of an acceptance
method. This is a sample-level planning budget, not a universal plugin limit.
It never delays correction after evidence already invalidates a claim or scope.
