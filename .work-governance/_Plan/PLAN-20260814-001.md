# Unify Plan source discovery for history and authority

Goal: Implement the approved PlanSourceIndex refactor so plan authority inspection, goal initialization, and plan history commands share one canonical source discovery path, preserving NON_AUTHORITY handling for historical docs/Plan.md and reducing workflow friction.

## Success Conditions
- A new canonical Plan source index module discovers active indexed Plans, conventional Plan.md/docs/Plan.md candidates, legacy root Plans, archives or completed governance Plans, hashes, parse summaries, signals, and agent-supplied classifications.
- plan authority inspect/check and goal init consume the shared source index without losing existing authority semantics.
- plan history list/show exposes conventional historical Plan candidates with classification, reason, sha256, and parse state, while retaining loose history behavior for completed governed Plans.
- Duplicated scanner behavior is removed or narrowed so authority/history no longer diverge for conventional Plan candidates.
- Schema-v5 tests cover unmanaged empty plus historical docs/Plan.md, active Plan plus historical candidate, likely-authority conflict, completed history, and goal init authority candidate preservation.
- Full local validation passes and the change is committed locally; Push/MR/live Plugin activation remain separate confirmation gates.

## Tasks
- T-001: Map current authority/history/goal-init scanner implementation and define the exact PlanSourceIndex integration points.
- T-002: Implement the shared PlanSourceIndex module and rewire authority inspection, goal init candidate capture, and history list/show to use it.
- T-003: Add focused schema-v5/current-history tests and update generated CLI/docs artifacts required by the executable surface.
- T-004: Run full validation, independent review, closeout, and create the local commit while preserving Push/MR/live activation as pending external gates.
