# Workctl kernel directory refactor

## Goal
Complete the local destructive refactor that makes workctl_modules/kernel/ the sole current controller kernel package, keeps workctl.py as a thin stable entrypoint, updates affected tests and documentation, validates the result, and creates one local commit without Push or live Plugin activation.

## Success Conditions
- The current kernel implementation lives under plugins/work-governance/scripts/workctl_modules/kernel/ rather than a version-suffixed directory.
- plugins/work-governance/scripts/workctl.py remains a stable, minimal executable entrypoint that delegates to the current kernel.
- Runtime bundling, tests, documentation, generated CLI reference, and metadata checks are aligned with the new layout.
- Focused and broad local validation pass or any residual gaps are explicitly reported with evidence.
- A local commit records only this bounded implementation and governance Plan state; Push and live activation remain excluded.

## Tasks
- T-001: Inspect current source, module, test, docs, and runtime bundle dependencies for workctl.py and workctl_modules.
- T-002: Move controller implementation into workctl_modules/kernel/ and replace workctl.py with a thin executable wrapper.
- T-003: Update tests, documentation, generated references, and runtime bundle handling affected by the new kernel layout.
- T-004: Run focused and broad local validation, fixing evidence-backed defects in scope.
- T-005: Review changed-file scope, record final evidence, and create one local commit without Push or activation.
